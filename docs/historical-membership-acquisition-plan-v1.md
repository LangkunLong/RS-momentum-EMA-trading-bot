## Proposed artifacts and provenance

Keep the upstream per-index event inputs and the normalized production-union artifact distinct:

1. **Per-index event CSVs** preserve the normalizer's exact input columns: `effective_date,ticker,member`. Keep a separate file for `sp500`, `nasdaq100`, and `russell2000`. `member` is `1` for an addition and `0` for a removal. Seed rows use the contract's initial state date; subsequent rows use the provider's exact effective date, not the announcement date and not a manually shifted session.
2. **Event-evidence ledger** binds each event to `universe_id`, provider ticker, action, exact effective date, source publication date, source URL, source SHA-256, source locator (table/page/row), and review status. Keep corrected or amended notices linked to the original claim instead of overwriting it.
3. **Source provenance per index** binds the exact CSV and ledger bytes, source-document manifests, source type (primary/secondary), retrieval timestamp, date window, event/symbol counts, seed basis, event types covered, exclusions, and access/license disposition. No current ETF/fund holdings are admitted as index membership.
4. **Price identity contract** retains each canonical ticker's provider symbol, admitted dates, `chain_id`, continuity kind, `warmup_predecessor`, and factor-anchor status, with the existing request-contract digest.
5. **Explicit price identity transitions** go into the v3 prices provenance under the existing exact fields: `effective_date`, `predecessor`, `successor`, `chain_id`, `continuity_kind`. Store transitions canonically sorted and record `price_identity_transitions_sha256` beside `price_identity_request_contracts_sha256`.
6. **Normalized membership artifact** uses the existing v3 rows: `effective_date,security_lineage_id,universe_id,member`. Preserve separate index affiliations for overlaps; downstream union queries deduplicate the lineage per session. A verified predecessor/successor rename is coalesced as continuous membership within one index; genuinely short-lived additions and removals remain dated events.

## Transition authentication path

The 30-row identity map is an investigation index, not a source of automatic transition rows. For every non-null `warmup_predecessor` candidate:

1. Verify the full source `price_identity_request_contracts` hash and find the exact predecessor and successor identity rows. Confirm one stable `chain_id`, non-overlapping/chronological admitted dates, and the exact successor effective date.
2. Retain primary evidence for the identity relationship and its effective date: issuer or exchange ticker/CUSIP-independent security notices, filed issuer documents that identify the same legal issuer/share class, and index/provider notices that state when the symbol change takes effect. Keep company rename, listing transfer, acquired company, spinoff, and successor issuer as distinct cases.
3. Have a reviewer affirm same-security continuity; do not join two tickers based only on a similar company name or same-day index add/remove. If a merger produces a new successor security, use a new lineage unless accepted accounting-acquirer continuity is documented by the accepted policy.
4. Emit the explicit v3 transition only after its evidence hashes and ticker/date/lineage links pass review. Validate the graph for exactly one active identity per lineage and no ambiguous predecessor/successor edges. Do not modify `core/pit_data.py` or other shared readers as part of this plan; coordinate any integration change with the lead.
5. Run the normalizer with the exact transition list. Its rename exception requires an authenticated same-date successor membership addition and an active prior index affiliation; unrelated out-of-range events still fail.

## Acceptance checks

1. For each index, source files and provenance cover the complete contract window, including an authoritative initial state and every addition/removal through 2025-12-31. The event stream replays without duplicate additions, inactive removals, unexplained gaps, or invented ticker changes.
2. Each retained source hash, event citation, effective date, ticker, index identity, source publication date, and source-use disposition can be reproduced from the retained evidence. Preliminary Russell lists are not labeled final when later official updates exist.
3. Every source ticker maps to exactly one authenticated price identity at the event boundary. Every cross-ticker continuity edge has primary identity/effective-date evidence and is bound to the exact identity-contract digest.
4. The combined normalized artifact has the accepted v3 schema and source hashes. Overlap fixtures and known source examples preserve two index tags for one lineage, rename continuity, and brief add/remove periods; event dates and membership states match independent official snapshots or notices.
5. Publish per-index/pooled coverage, overlap counts, event and lineage counts, explicit exclusions, unresolved identity cases, and source-terms status. A complete pass is not claimed for an index with missing seed history, unauthenticated transitions, or unresolved rights.
