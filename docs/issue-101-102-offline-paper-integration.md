# Issues #101 and #102: offline paper integration

This change joins the accepted historical-to-fake-paper implementation to current `main`. It activates the selected frozen V3 policy path in `auto_trader`, persists policy decisions and broker facts through the policy store, and binds paper entry, stop, sell, restart, and reconciliation behavior to the order workflow. The existing addition, replacement, and PIT parity implementations remain in place.

## Current-main integration boundary

The current-main three-way merge keeps later addition and parity code. Two import conflicts in `core/order_manager.py` were resolved by retaining both addition and paper-policy dependencies. Four policy modules absent from main are included because the integrated call graph and offline tests use them.

Current-main `AllocationSnapshotV3` requires `base.pending_entries_remaining <= portfolio.pending_entry_count`. The paper allocator now projects the selected queue count for each allocation snapshot, matching the historical adapter, while leaving the reconciled account facts unchanged. This is a material interface difference from W33, so W33 acceptance does not transfer automatically to this merged revision.

The portable synthetic parity fixtures cover two frozen policy variants, real historical simulator and current paper calls, partial/full fills, duplicate callback idempotency, stop protection, and restart reconciliation. The selected repo tests use fake clients and synthetic input. For Windows test runs, set `AGENT_LOOP_TEST_TMP_ROOT` to a short absolute directory outside the checkout to avoid path-length failures.

All 23 Issue #102 accepted selector-map targets now have direct test functions on this branch. The 39 W33 corrected selectors translate one-for-one to direct repo tests and collect the same 48 parameterized instances. The `test_corrected.py` aliases are not duplicated in the published suite; their source tests run directly. Three STOP/protective-sell source tests and three public delivery tests missing from current main were ported. The recovered STOP operation-limit assertion was also restored as a separate runnable test. The synthetic JSON received only a final newline for repository formatting; its current-head SHA-256 pin is `6085a26ec832039aaa8dd906801142bdf174107ad0cfe6d0f62283be2834d051`.

The exact current-head selection is committed in `tests/paper_verification/corrected_selectors.txt` (SHA-256 `1ec427e026f4a184e0ded0f966927bd14f76fe3eb6efa7f14a32c2699a0360a4`). From the repository root, run `python tools/run_paper_corrected_selection.py --collect-only` to confirm 48 instances, then `python tools/run_paper_corrected_selection.py` for the offline run. The runner blocks network connections. Its selector list has no dependency on the local W33 scratch package.
